# Nightwell Chat Server v0.11.9

Windows-сервер Nightwell Chat без контейнеров. Python 3.12 + FastAPI + SQLite. **Отдельный сервис от Nightwell Music**.

## Запуск на Windows

1. Установите Python 3.12. Команда проверки: `py -3.12 --version`.
2. Распакуйте файлы поверх старого сервера Chat. **Не удаляйте `.env` и `data/`**.
3. Остановите старый Chat через `Stop_Nightwell_Chat.bat` или `Ctrl+C` в окне его запуска. Caddy и Nightwell Music не трогайте.
4. Дважды нажмите `Start_Nightwell_Chat.bat`. Он создаст `.venv`, установит зависимости и запустит сервер.
5. Проверьте `http://127.0.0.1:8009/health`.

Если сервер запускается впервые, BAT-файл сам создаст `.env` со случайным секретом. Не заменяйте его при обновлениях. Для резервной копии сохраняйте **вместе** `.env`, `data/nightwell_chat.db` и `data/media/`.

## Caddy

Сохраняйте ваш существующий `Caddyfile` для двух сайтов:

```caddyfile
music.nightwell.fun {
    reverse_proxy 127.0.0.1:8080
}

chat.nightwell.fun {
    reverse_proxy 127.0.0.1:8009
}
```

Nightwell Chat слушает **только** `127.0.0.1:8009`, а публичный доступ идёт через Caddy на HTTPS 443. Второй экземпляр Caddy не запускайте. Порт 8009 на роутере открывать не требуется.

## Что есть в API

- Регистрация/вход по телефону и паролю **без SMS**. Номер проверяется **только по формату**, а не на принадлежность владельцу.
- Сохранён прежний вход по логину и паролю. К существующему аккаунту можно привязать номер.
- Поиск по телефону только пользователей с добровольно включённой видимостью номера. Приложение должно запрашивать разрешение на контакты и отправлять лишь выбранный номер.
- Личные и групповые чаты, отправка сообщений, ответы, реакции, редактирование и удаление, история и статусы прочтения.
- Загрузка и получение аватарок, изображений и файлов. Максимальный размер вложения 50 МБ. Доступ к вложениям разрешён только участникам чата. Фотографии конвертируются в JPEG без EXIF.
- Аудиозвонки один на один: создание, принятие, отклонение, завершение, сигнализация WebRTC и отдельная HTTPS-страница соединения.

## Ограничения тестовой версии

- **Без SMS нет реальной проверки владельца номера.** Нельзя доверять телефонному номеру как подтверждённой личности.
- У звонков нет системных VoIP push-вызовов и CallKit. Для мобильных сетей может потребоваться отдельный TURN-сервер. Python-сервер передаёт только WebRTC-сигнализацию, а аудио идёт напрямую между клиентами или через TURN.
- Нет сквозного шифрования сообщений, сканирования загруженных файлов и зрелой антиспам-системы.
- Один процесс SQLite/WebSocket, подходит прежде всего для небольшой тестовой аудитории, а не массового публичного запуска.
- Обновлённые iOS/Android-клиенты должны соответствовать этим эндпоинтам. Этот ZIP содержит только сервер.

## Проверка

В папке `server`, после установки зависимостей и с отдельной тестовой базой:

```powershell
$env:SECRET_KEY = 'local-test-secret-long-enough-only-for-tests'
$env:DB_PATH = "$env:TEMP\nightwell_test.sqlite"
..\.venv\Scripts\python.exe -m pytest -q
```

**Не запускайте тесты на рабочей базе.**

## Звонки 0.11.6

Перед проверкой звонков обязательно обновите сервер и оба клиента до 0.11.6. В версии добавлены защищённые статус и завершение звонка по call-ticket, автоматическое закрытие интерфейса и нативные кнопки. WebRTC по-прежнему работает в защищённом WebView, для некоторых сетей потребуется TURN. Входящие на iOS проверяются при открытом приложении; системные VoIP-уведомления для фонового режима ещё не реализованы.

## 0.11.8: микрофон и звонки

WebRTC сообщает конкретную причину ошибки микрофона. В Android повторный запуск захвата звука не перезагружает страницу или сигнализацию вызова. На Windows/BlueStacks при NotReadableError нужно проверить системное устройство ввода, разрешения Windows и выбор микрофона в настройках BlueStacks. Для новой диагностики требуется сервер с обновлённым `server/call_page.html`.

## 0.11.9: звонки и Android-клавиатура

В Android добавлена корректная обработка экранной клавиатуры через IME Insets. Строка ввода остаётся над клавиатурой. В экране звонка ошибка микрофона больше не отправляет пользователя телефона в BlueStacks. Повторная попытка захвата звука использует обычный микрофон, если устройство не поддерживает дополнительные аудиопараметры. Для WebRTC добавлены ограничение ожидания, одна автоматическая попытка ICE restart и понятное объяснение ошибки соединения.

Обновлённый `server/call_page.html` получает адреса ICE/TURN через защищённый `GET /calls/{id}/ice`. Секреты TURN больше не находятся в публичной HTML-странице. Обновляйте `server/app.py` и `server/call_page.html` **вместе**.

## TURN для стабильных звонков с мобильного интернета

STUN не гарантирует соединения через операторский CGNAT, поэтому для устойчивой связи между мобильными телефонами установите отдельный TURN-релей. Caddy и Cloudflare Tunnel не заменяют TURN для передачи WebRTC-аудио. Используйте VPS с публичным IPv4 и DNS-именем, например `turn.nightwell.fun`. Если запись DNS обслуживает Cloudflare, настройте **DNS only**, без проксирования HTTP.

Пример установки `coturn` на Ubuntu:

```bash
sudo apt update && sudo apt install -y coturn
```

В `/etc/turnserver.conf`:

```ini
listening-port=3478
fingerprint
realm=nightwell.fun
use-auth-secret
static-auth-secret=PUT_A_SEPARATE_RANDOM_SHARED_SECRET_HERE
min-port=49160
max-port=49200
no-multicast-peers
no-loopback-peers
```

Если VPS или TURN-сервер находится за NAT, добавьте `external-ip=PUBLIC_IPV4`. В Ubuntu включите `TURNSERVER_ENABLED=1` в `/etc/default/coturn`, затем выполните `sudo systemctl enable --now coturn`. Откройте входящие **3478/UDP**, **3478/TCP** и **49160–49200/UDP** в файрволе VPS и у хостинг-провайдера.

В **существующий** `.env` Windows-сервера Chat добавьте:

```dotenv
NIGHTWELL_TURN_URL=turn:turn.nightwell.fun:3478?transport=udp,turn:turn.nightwell.fun:3478?transport=tcp
NIGHTWELL_TURN_SHARED_SECRET=PUT_THE_SAME_RANDOM_SHARED_SECRET_HERE
```

Секрет в `.env` должен совпадать с `static-auth-secret` на coturn, но не с `SECRET_KEY` основного чата. Перезапустите только Chat BAT-файлом. Он использует сохранённую базу данных, аккаунты и переписки.

При `NIGHTWELL_TURN_SHARED_SECRET` приложение получает временные TURN-данные после проверки call-ticket. Старые параметры `NIGHTWELL_TURN_USERNAME` и `NIGHTWELL_TURN_PASSWORD` тоже поддерживаются для внешнего TURN-провайдера, но предпочтительнее временные учётные данные. Без реально работающего TURN на сложных сетях соединение по-прежнему может не установиться, теперь вместо вечной загрузки появится объяснение проблемы.
