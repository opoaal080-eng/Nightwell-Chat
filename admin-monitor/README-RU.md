# Nightwell Admin: мониторинг компьютера

Добавляет в приложение Nightwell Admin вкладку «Сервер» с реальными показателями Windows-компьютера: CPU, ядра, RAM, накопители, чтение/запись дисков, сетевой трафик, время работы, GPU NVIDIA и доступные датчики температур.

**Не требует Docker.** Агент независим от Music и Chat, поэтому данные хоста доступны при остановке одного из сервисов.

## 1. Установка на Windows

1. Скопируйте всю папку admin-monitor из репозитория на Windows-компьютер, где работают Nightwell Music и Chat.
2. Убедитесь, что установлен Python 3.12. Пакет psutil установится автоматически в отдельную .venv.
3. Запустите admin-monitor/Start_Nightwell_Monitor.bat.
4. При первом запуске появится файл admin-monitor/.env со случайным секретом NIGHTWELL_MONITOR_TOKEN и портом 8091. **Не удаляйте этот файл при обновлении и не загружайте его на GitHub.**
5. В Nightwell Admin на iPhone откройте «Настройки» → «Мониторинг компьютера» и введите значение NIGHTWELL_MONITOR_TOKEN, без имени переменной. Ключ сохранится в Keychain. Ключ управления сервисами остаётся отдельным.
6. Оставьте BAT запущенным или настройте автозапуск через Планировщик заданий Windows. Сервис слушает только 127.0.0.1:8091.

Проверка на Windows через PowerShell:

    Get-NetTCPConnection -LocalPort 8091 -State Listen

Доступ к метрикам без правильного Bearer-ключа невозможен. Не открывайте порт 8091 на роутере.

## 2. Настроить существующий Caddy

Внутри **существующего** блока admin.nightwell.fun добавьте маршрутизацию мониторинга. Остальные маршруты должны по-прежнему вести на работающий Nightwell Admin Bridge.

Пример Caddyfile (замените ВАШ_ПОРТ_BRIDGE на реальный локальный порт моста):

    admin.nightwell.fun {
        @monitor path /v1/system/metrics
        handle @monitor {
            reverse_proxy 127.0.0.1:8091
        }
        handle {
            reverse_proxy 127.0.0.1:ВАШ_ПОРТ_BRIDGE
        }
    }

Если блок сайта уже существует, **не создавайте второй такой же блок**. Сохраните действующие маршруты команд управления, push и других операций.

Проверка: caddy validate --config Caddyfile, затем caddy reload --config Caddyfile из папки с Caddyfile.

iPhone обращается к https://admin.nightwell.fun/v1/system/metrics с отдельным ключом мониторинга. HTTPS обслуживает Caddy. Не публикуйте токен в URL или логах.

## 3. Что отображается

- CPU: текущая загрузка, модель, количество ядер и потоков, загрузка логических ядер.
- RAM: общий и занятый объём, процент заполнения.
- Диски: заполнение, скорость чтения и записи. Скорости появляются после второго измерения.
- Сеть: входящая/исходящая скорость и суммарный трафик с загрузки ОС.
- GPU NVIDIA: название, загрузка, использование видеопамяти и температура, если доступен nvidia-smi.
- Температуры: доступные ОС датчики. На Windows для CPU может потребоваться LibreHardwareMonitor с поддержкой WMI.
- Состояние: локальные порты Music 8080 и Chat 8009, время работы Windows.
- История: график CPU/RAM за последние 120 измерений в открытом приложении.

Отсутствие датчика отображается как «недоступно», а не как придуманное значение.

## Безопасность и диагностика

- Агент слушает только 127.0.0.1, принимает только GET /v1/system/metrics с Bearer-ключом и сравнивает ключи за постоянное время.
- Нет CORS-разрешений, удалённого выполнения команд, чтения пользовательских файлов.
- Ответы помечены Cache-Control: no-store.
- В настройках iPhone ключ мониторинга хранится через Keychain, не через UserDefaults.
- Автообновление работает каждые три секунды, пока экран открыт и приложение активно.
- Для проверки агента: python -m unittest discover -s admin-monitor/tests -v после установки psutil.

**Важно:** публикация на GitHub не обновляет BAT, Caddy и процессы на вашем Windows-компьютере. Настройку на самом сервере нужно выполнить отдельно.
